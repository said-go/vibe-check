# Канбан проекта «ВАЙБЧЕК»

Рабочие задачи ведутся в [GitHub Issues](https://github.com/said-go/vibe-check/issues). Первый релиз сгруппирован в [milestone MVP](https://github.com/said-go/vibe-check/milestone/1).

## Текущее состояние

Статус на 14 ноября 2026 года сверён с критериями [плана разработки](docs/VibeCheck-development-plan.docx), исходным кодом и проверками. Локальный основной сценарий работает; публичный HTTPS-релиз с AI ещё не подтверждён. Статический Sites остаётся демонстрацией интерфейса.

| --- | --- | --- |
| 01. Версии PWA | Код и автотесты готовы | HTML и ресурсы связаны хешами; обновление не прерывает открытый анализ. Несколько настоящих вкладок и устройства — часть шагов 08/14 |
| 02. Кеш при ошибках | Код и автотесты готовы | Ошибки не заменяют оболочку; API и фото не кешируются. Проверка офлайна на устройствах ещё нужна |
| 03. Срок анализа | Готово | Общий AI-дедлайн 110 секунд, клиентский — 125; повтор и отмена покрыты тестами |
| 04. Ошибки и повтор | Готово | Причины отказа, Retry-After и идемпотентность; кеш результата ограничен одним процессом и сроком хранения |
| 05. Уверенность и человек | Код готов, калибровка открыта | Ноль/несколько людей, невидимая одежда и уверенность ниже 20 не дают обычного вердикта. Проверка порогов — шаг 07 |
| 06. Приоритет категорий | Код готов, смысловая проверка открыта | Улыбка не перекрывает выраженный стиль автоматически. Согласованный набор примеров ещё нужен |
| 07. Оценка AI | Инструменты готовы, замеры открыты | collect-evaluation сохраняет каждый результат; evaluate объединяет набор и проверяет ожидаемое количество. Синтетические тесты не измеряют точность AI |
| 08. Фото и мобильный сценарий | Частично | Сжатие, ограничения размера, таймаут декодирования, JPEG EXIF-ориентация, повторный выбор и клавиатура проверены автоматически. Реальные камеры, HEIC, поворот и память на устройствах ещё требуют проверки |
| 09. Расходы | Инструменты готовы | Учёт попыток и токенов; оценка рублей по явно переданному тарифу с версией и указанной моделью. Неизвестные данные дают частичный отчёт. Реальный тариф и сверка с облачным счётом ещё нужны |
| 10. Общий облачный лимит | Код готов, облачная настройка открыта | Redis атомарно ограничивает общий часовой бюджет; при сбое AI блокируется. TLS, сохранность Redis, доверенные прокси и масштабирование нужно проверить в целевой среде |

| 12. Сборка и диагностика | Готово | .dockerignore, ограниченные по времени команды, журналы без фото/ключей, проверка хешей и состава PWA. Готовность Redis проверяется PING без расходования квоты; отказ подтверждён на локальном сервере |
| 13. Автоматические сценарии | Готово для покрытых сценариев | Go, UI, история, карточки, кеш, deployment и настоящий Redis в CI. Имитации DOM/IndexedDB не заменяют реальные устройства |
| 14. Телефоны и аудитория | Открыто | Нужны Android/iPhone и участники целевой аудитории; списка проверенных устройств и замечаний по текстам пока нет |

## Подтверждённые проверки

Дополнительный аудит: исправлены поздние асинхронные действия карточки результата и обработка некорректной даты в истории. Сборщик признаков теперь возвращает уже полученные случаи при последующей ошибке/отмене; сохранённые checkpoint-файлы и раньше оставались на диске. Повторный аудит серверных лимитов и EXIF не выявил новых воспроизводимых дефектов.

Текущий блок: локальный preflight прошёл, включая 40 Node-тестов и 30 deployment-проверок. Независимый агент проверил откат и расчёт тарифа; реальных облачных операций и платных AI-вызовов не было. Последний статус CI доступен в GitHub Actions.

Базовая проверенная версия — `eb5510b`: [успешный CI](https://github.com/said-go/vibe-check/actions/runs/43590934561). В нём прошли Go с race detector, go vet, синтетическая оценка с проверкой полноты, 34 Node-теста, сборка Docker, 21 проверка deployment и конкурентные запросы к настоящему Redis. Числа 34 и 21 повторно подтверждены локально при сверке доски. Результат текущих изменений фиксируется после общей проверки.

Ранее через браузер проверены согласие, загрузка двух заданных фото после сжатия и повторный выбор файла. Это не является проверкой всей выборки AI, мобильной камеры, установки PWA или экранного диктора. Локально Docker daemon недоступен, yc не установлен; сборка образа подтверждена CI, облачные ресурсы в этих блоках не создавались.

## Следующие действия

Подготовлены возврат образа по точному digest, расчёт стоимости по заданному версионированному тарифу, проверка Redis и исправление поворота JPEG. Следующие критерии готовности требуют реальных входных данных или целевой среды; добавление новых функций не заменяет эти проверки.

Для завершения релиза нужны входные данные и среда:

- Шаги 06–07: согласованные фото, допустимые категории и порог приемлемой точности; затем реальный отчёт с отказами и повторяемостью. Фотографии не публикуются в GitHub.
- Шаги 08/14: реальные Android/iPhone и пользователи региона для проверки камеры, галереи, установки, офлайна и понятности шуток.
- Шаги 10/15: доступ к Yandex Cloud, ID ресурсов, секреты в Lockbox, защищённый Redis, решение по бюджету; после настройки — HTTPS-проверка лимитов, рестарта и возврата версии.

Секреты в чат не отправляются. Аккаунты, синхронизация, ежедневные задания и другие функции из бэклога не заменяют эти критерии первого релиза.

## Правила доски

- `priority:P0` — необходимо для основного сценария MVP.
- `priority:P1` — важно для полноценного первого релиза.
- `priority:P2` — развитие после проверки MVP.
- Для перемещения задачи меняется метка `status:backlog`, `status:ready` или `status:in-progress`.
- Завершённая задача закрывается как `completed`.
- Новая задача должна содержать критерий готовности и зависимости.
