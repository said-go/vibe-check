# Канбан проекта «ВАЙБЧЕК»

Рабочие задачи ведутся в [GitHub Issues](https://github.com/said-go/vibe-check/issues). Первый релиз сгруппирован в [milestone MVP](https://github.com/said-go/vibe-check/milestone/1).

## В работе

Локальный основной сценарий реализован. Статус этапов из [плана разработки](docs/VibeCheck-development-plan.docx) обновлён 14 ноября 2026 года после совместной работы трёх агентов и проверки интеграции.

| Шаг плана | Статус | Что сделано или осталось |
| --- | --- | --- |
| 01. Версии PWA | Готово | Имена JS/CSS с хешами, согласованные HTML/SW, проверка сборки в CI |
| 02. Кеш и обновления | Готово | Оболочка своей версии, ошибки не кешируются, активный анализ не прерывается обновлением |
| 03. Общий срок анализа | Готово | 110 секунд на AI с повтором, отмена; 125 секунд на клиентский сценарий |
| 04. Ошибки и повтор | Готово | Retry-After с отсчётом, отмена, понятные причины отказа, проверка структуры результата |
| 05. Уверенность и люди | Готово в коде | Нет вердикта при количестве людей не равном одному, отсутствии одежды или уверенности ниже 20; калибровка — шаг 07 |
| 06. Приоритет категорий | Готово в коде | Улыбка не перебивает выраженный стиль; сценарии покрыты тестами, пороги пока предварительные |
| 07. Набор фото для оценки | Инструменты готовы | Есть сбор признаков и сравнение с ожидаемыми категориями. Согласованный набор и реальные замеры ошибок ещё нужны |
| 08. Фото и мобильные устройства | Частично | Сжатие, понятный отказ для слишком узкого кадра, повторный выбор файла; реальные камеры, HEIC и установка на телефоны ещё не проверены |
| 09. Учёт платных вызовов | Готово для экземпляра | Каждый повтор занимает бюджет; журналы попыток, HTTP-статусов и токенов без фото/ключа |
| 10. Общий облачный лимит | Частично | Доверенные прокси поддержаны в коде. Нужны общий бюджет/store, ограничения масштабирования и проверка настройки в облаке |
| 11. Приватные ответы | Готово локально | Файл исключён из Git/Docker, валидируется при старте; две исходные фотографии проверены через PWA без AI. Старые значения остаются в истории Git |
| 12. Подготовка сборки | Готово | .dockerignore, проверка Docker с таймаутом 8 секунд, preflight и smoke различают AI и приватные ответы |
| 13. Поведенческие тесты | Готово для автоматизируемой части | Go интеграция, дедлайны, отмена, бюджеты; 31 Node-тест UI, истории, карточек и SW. Реальные браузеры/устройства не заменены имитациями |
| 14. Проверка на телефонах и аудитории | Открыто | Нужны устройства и участники из целевой аудитории |
| 15. Облачный релиз | Открыто | Нужны доступ к Yandex Cloud, ресурсы, секрет, бюджет и проверка публичного HTTPS |

Локальный preflight прошёл: Go-тесты, go vet, синтаксис JS, согласованность PWA и 31 поведенческий тест. Через браузер проверены выбор файла, согласие, оба приватных результата при отключённом AI и повторный выбор фотографии. Docker daemon локально недоступен, yc не установлен; облачные ресурсы не создавались.

## Готово к работе

Четвёртый автономный блок (14 ноября):

- Платный лимит больше не блокирует визуально подтверждённые приватные ответы. Подставленный отпечаток не обходит лимит, параллельность ограничена; отмена до вызова не расходует бюджет, зарезервированная квота защищена.
- Сборщик выборки проверяет все файлы до первого вызова и сохраняет каждый успешный результат в новый каталог. Ошибка очередного файла или провайдера не удаляет уже записанные результаты. Автоматического продолжения нет.
- Проверка релиза сверяет хеши JS/CSS, PNG-иконки и состав Service Worker. 14 локальных regression-проверок и smoke на реальном локальном сервере прошли без AI-вызовов.

Третий автономный блок (14 ноября):

- Шаг 07: добавлен `collect-evaluation` для сбора признаков из локального manifest фотографий через AI, отдельно от приватных ответов. По умолчанию отправка запрещена; нужен `-allow-paid`, лимит попыток и настроенное окружение. Выход содержит признаки и номера примеров, без снимков и путей. Реальные платные запросы в этом блоке не выполнялись, точность AI пока не измерена.
- Шаг 13: история устойчиво читает повреждённые записи; сохранение и ограничение 50 записей атомарны. Добавлены проверки истории и PNG-карточек — всего 31 Node-тест с имитацией IndexedDB/canvas.
- Шаг 12/15: внешние Docker/yc команды ограничены по времени; добавлены 10 локальных проверок deploy/smoke без доступа к облаку. Проверки подключены к preflight и CI.

Остаются: согласованные реальные примеры для оценки, проверка устройств и аудитории, общий бюджет нескольких серверов, настройка облачных ресурсов и HTTPS-релиз. Новые инструменты не означают завершения этих проверок.

Дополнение от 14 ноября — следующий автономный этап:

- Шаг 07: подготовлен `go run ./cmd/evaluate -input internal/evaluation/testdata/synthetic.json` (из backend): реальные правила scoring, сводка и таблица ошибок, JSON-отчёт. Пять синтетических примеров проверяют правила, но не подтверждают точность распознавания фото. Согласованная выборка остаётся открытой задачей.
- Шаг 08/13: добавлены таймаут открытия фото, обработка пустых файлов, подсказка для неподдерживаемого HEIC и ограничение 100 Мп до canvas. Теперь 24 frontend-теста. Память самого декодера и реальные телефоны ещё требуют проверки.
- Шаг 10: реализован opt-in TRUSTED_PROXY_CIDRS с проверкой цепочки XFF и тестами подмены адресов. По умолчанию заголовок игнорируется. Общий бюджет нескольких экземпляров и проверка конфигурации реального прокси остаются открытыми.
- Шаг 15: smoke проверяет также доступность версионированных JS/CSS. Локальная проверка прошла без обращения к AI; облачный релиз не выполнялся.

## Правила доски

- `priority:P0` — необходимо для основного сценария MVP.
- `priority:P1` — важно для полноценного первого релиза.
- `priority:P2` — развитие после проверки MVP.
- Для перемещения задачи меняется метка `status:backlog`, `status:ready` или `status:in-progress`.
- Завершённая задача закрывается как `completed`.
- Новая задача должна содержать критерий готовности и зависимости.
