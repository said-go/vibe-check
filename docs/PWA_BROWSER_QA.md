# Проверка двух версий PWA в браузере

## Необязательный замер JS heap

Для локальной проверки памяти перед запуском стенда задайте `PWA_QA_MEMORY=1`. В QA-оболочку добавится раскрывающаяся панель с кнопкой «Снять замер памяти». Она читает `performance.memory` в настоящем браузере и показывает используемый/выделенный JS heap в MiB; если API нет, явно сообщает, что замер не выполнен. Скрипт не попадает в production `dist`, данные не отправляются на сервер. Таблица ограничена 100 строками.

Снимите исходное значение, затем повторите выбор синтетического файла → согласие → результат → закрытие окна, снимая значение после каждого закрытия. Запишите число циклов и размеры файла. Не сравнивайте замеры разных вкладок или браузеров как один ряд. API нестандартный, может округлять значения; сборка мусора происходит независимо. Эти цифры не включают всю память вкладки, декодированные изображения или GPU и сами по себе не доказывают наличие/отсутствие утечки. Для расследования роста используйте [Chrome Task Manager и Memory profiling](https://developer.chrome.com/docs/devtools/memory-problems).

Стенд работает только на `127.0.0.1:8092`, выдаёт синтетический отчёт и не обращается к AI. Загруженные байты отбрасываются, фотографии не записываются. Версии создаются в игнорируемом `backend/private/pwa-browser-qa`, production-файлы не меняются.

1. Выполнить `node scripts/build-pwa.mjs`, затем `node scripts/qa-pwa-server.cjs`. Каждый запуск заново копирует текущую сборку и создаёт V1/V2 с разными HTML, CSS-хешами и именами кешей. Файл состояния сохраняется между запусками; перед новым испытанием установить `{"version":"v1","available":true}` в `backend/private/pwa-browser-qa/state.json`.
2. В отдельном браузерном профиле/оригине открыть вкладку A. Убедиться, что виден `ТЕСТ ВАЙБЧЕК V1 — БЕЗ AI`. Выбрать синтетический JPEG, подтвердить обработку, получить отчёт и сохранить его в историю. Оставить отчёт открытым. Реальные пользовательские фото не нужны.
3. Поменять файл состояния на `{"version":"v2","available":true}`. Открыть вкладку B того же origin. Она может показывать кешированную V1 — это ожидаемо до активации обновления. Дождаться предложения обновить приложение и нажать кнопку обновления в B.
4. Проверить, что B показывает V2, а открытый отчёт в A не исчез и не перезагрузился. Закрыть отчёт A: должно появиться предложение обновления. Нажать его и проверить V2, сохранённую историю и возможность скачать карточку.
5. Для проверки недоступности сервера установить `available:false` (сервер отвечает 503) либо остановить процесс стенда. Перезагрузить страницу: оболочка и история должны сохраниться, анализ должен сообщать об отсутствии связи. Не путать этот сценарий с полноценной имитацией отключения всех сетевых ресурсов устройства.
6. Восстановить сервер, закрыть временные вкладки и остановить стенд. Не удалять историю или кеши рабочего публичного сайта ради теста.

`GET /__qa/status` показывает активную серверную версию и количество синтетических POST; это не версия уже установленного Service Worker. Новый origin можно получить через `PWA_QA_PORT`, чтобы повторить сценарий первого посещения без удаления прежних данных браузера.

Проверка HTTP-маркеров и unit-тесты не заменяют выполнение этих шагов в настоящем браузере. Результаты браузерного прогона следует фиксировать отдельно, включая сохранение отчёта, историю, фактические V1/V2 и ограничения использованного браузера.

## Выполнено 15 ноября 2026

В браузере проверен переход V1 → V2 в двух вкладках: обновление второй вкладки сохранило открытый отчёт первой; после закрытия отчёта первая предложила обновление. История сохранилась после обновления и перезагрузки при HTTP 503 от стенда. Использован один синтетический анализ без AI. Скачивание PNG в этом прогоне не проверялось.

Клавиатурой проверены переход к основному содержимому, закрытие отчёта и возврат фокуса, удаление записи с переводом фокуса к заголовку истории. При viewport 320 × 640 горизонтального переполнения нет (clientWidth и scrollWidth — 305). Физические телефоны, экранный диктор, увеличение 200% и полное отключение сети остаются отдельными проверками.

## Настоящий масштаб Chrome — 15 ноября 2026

На локальном стенде 8094 с синтетическим фото проверен обычный Chrome Windows при 200% и 400% (значения подтверждены индикатором браузера). При 400% пройдены прокрутка главной, выбор файла, согласие клавишами Tab/Space, анализ на mock API, просмотр результата и переход к действиям отчёта клавишей Tab. При 200% осмотрены главная и действия отчёта. Кнопки доступны, содержимое модального окна прокручивается; в проверенном сценарии обрезания по ширине не обнаружено. Фото — синтетическое, AI не вызывался. Масштаб возвращён командой Ctrl+0, временная вкладка закрыта. Это не аудит всех страниц/браузеров и не проверка экранным диктором или физической камеры.

## Замер памяти и DevTools Offline — 15 ноября 2026

В отдельной вкладке обычного Chrome включён Go offline в DevTools, выполнен reload: кешированная оболочка загрузилась, появились «НЕТ ПОДКЛЮЧЕНИЯ К СЕТИ» и «Нет сети — новый AI-анализ недоступен». После Go online статус вернулся к подключённому серверу. Системная сеть не менялась. История с ранее сохранённой записью и отправка нового фото в этом офлайн-прогоне не проверялись. Это эмуляция полного отключения запросов вкладки, не выключение Wi-Fi устройства.

В in-app Chromium на QA 8095 выполнено пять циклов синтетического фото → согласие → mock-результат → закрытие. Performance.memory used/total JS heap (MiB): baseline 12.13/14.78; затем 5.68/7.69, 5.78/7.44, 6.10/7.69, 5.85/7.45, 5.88/7.44. Измерения приблизительные, GC не принуждался; учитываются приложение и тестовая панель. Короткий ряд не показывает монотонного роста, но не доказывает отсутствие утечек и не измеряет всю память процесса. Платных AI-вызовов нет.

Narrator доступен в Windows; реальное озвучивание не проверено, поскольку инструменты не позволяют прослушать речь. Статический аудит ARIA новых дефектов не выявил. Масштаб 200/400% подтверждён предыдущим Chrome-прогоном; production CSS/HTML в этом пакете не менялись.

## Расширенный прогон и переименование стенда — 15 ноября 2026

На QA 8096 в in-app Chromium выполнено 30 циклов выбора фото → согласия → синтетического результата → закрытия без зависаний. По очереди использованы JPEG 480×640 (10 736 байт), 1600×1200 (63 898 байт), 4000×3000 (397 010 байт), по 10 раз каждый. Личные фото и платный AI не использовались.

Исходный used/total JS heap — 12.13/14.28 MiB. Ряд used JS heap после каждого из 30 циклов, MiB:

```text
12.77, 13.26, 7.44, 7.72, 6.17, 7.37, 7.30, 6.19, 7.43, 7.36,
6.25, 7.44, 7.41, 6.28, 7.47, 7.45, 6.30, 7.49, 7.48, 6.31,
7.51, 7.50, 6.34, 7.52, 7.53, 6.35, 7.54, 7.56, 6.37, 7.53
```

Последний used/total — 7.53/8.93 MiB, через 123.9 секунды после запуска измерений. После начального пика 13.26 MiB значения возвращались в диапазон 6.17–7.72 MiB. Есть небольшой рост нижних значений; таблица измерений также растёт. Принудительной сборки мусора не было. Это наблюдение не доказывает отсутствие утечки и не охватывает память изображений, GPU и всего процесса.

На QA 8097 в Chrome Windows сохранён один синтетический отчёт, затем включён DevTools Offline и перезагружена страница. Видны сообщение «Нет сети — новый AI-анализ недоступен», одна запись истории и оценка 74/100. При остающемся включённым Offline из истории скачана PNG-карточка: Chrome подтвердил завершение загрузки (124 КБ). После проверки сеть восстановлена. Проверены список истории и скачивание карточки; отдельного открытия подробного отчёта из истории интерфейс не предоставляет. Физическое отключение сети устройства этим не проверено.

Стенд переименован в «ТЕСТ ВАЙБЧЕК — без AI»: изменены title, логотип, имя и описание manifest. Заметный баннер объясняет, что любое фото получает фиксированный ответ «Спортик». В Chrome проверены название вкладки, баннер и предлагаемое имя установки. Ранее установленное приложение может сохранять старое имя до обновления manifest.

**Открыто: обновление установленной PWA V1 → V2 в отдельном окне приложения.** Установка и этот переход не подтверждены: управление браузером было остановлено автоматической проверкой, не сумевшей уверенно определить URL на этапе установки. Успешная проверка двух обычных вкладок не закрывает этот пункт. По решению пользователя задача остаётся открытой.

Изменения относятся только к QA-инструментам и документации. Рабочий сайт не разворачивается; production-файлы не меняются.

Перед сохранением: 35 тестов history/pwa-upgrade прошли; node --check для обоих QA-скриптов и build-pwa.mjs --check успешны. Рабочая PWA сохранила версию 6c20da874833fa46.
