# VibeCheck Backend

Go API для приёма фото, извлечения признаков одежды через Yandex AI Studio и детерминированного расчёта результата. Backend раздаёт `dist/` на `/` и API на `/api`.

## Запуск

Из каталога `backend/` выполните `go run ./cmd/api`, предварительно задав `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в окружении. Без них development сервер запускается для проверки интерфейса, а обычный анализ возвращает `503 ai_unavailable`. В production отсутствие реквизитов блокирует запуск, кроме явно настроенного режима с непустым приватным файлом результатов.

`GET /api/healthz` показывает, что процесс жив. `GET /api/readyz` возвращает 200 и флаги `ai_available` / `presets_available`, если настроен хотя бы один путь анализа; иначе 503. Флаг AI подтверждает наличие конфигурации, а не действительность ключа. При размещении в Yandex Serverless Containers сервер слушает порт из `PORT`; явный `HTTP_ADDRESS` имеет приоритет.

```text
GET  /api/healthz
GET  /api/readyz
POST /api/v1/analyses
```

`POST /api/v1/analyses` принимает ровно одно поле `image` (JPEG/PNG, 128×128 или больше, до 20 мегапикселей) и ровно одно `privacy_consent=true`. Дубли полей отклоняются. Максимальный размер запроса 10 МБ. PWA уменьшает выбранное фото до 1600 пикселей по длинной стороне и сжимает в JPEG перед отправкой. Сервер проверяет и повторно кодирует его без EXIF; наш сервер не сохраняет изображение.

PWA передаёт `Idempotency-Key`, который остаётся прежним при повторе одного фото. Успешный результат и SHA-256 очищенного JPEG хранятся до 10 минут в памяти процесса, исходное фото в кеш не попадает. Повтор не вызывает AI и возвращает тот же `analysis_id`; тот же ключ с другим фото получает 409. После рестарта, на другой реплике или после сетевого таймаута у провайдера гарантии единственного платного вызова нет.

PWA также передаёт `X-Original-Image-SHA256` для точного совпадения с двумя согласованными снимками. Сервер сверяет отпечаток с визуальным признаком очищенного фото и возвращает заданный результат без вызова AI. Этот заголовок сам по себе не выбирает результат: чужое фото с подставленным отпечатком идёт обычным путём анализа.

## Настройки

| Переменная | По умолчанию |
|---|---|
| `APP_ENV` | `development` |
| `HTTP_ADDRESS` | `:8080` |
| `FRONTEND_DIR` | `../dist` |
| `HTTP_READ_TIMEOUT` | `30s` |
| `HTTP_WRITE_TIMEOUT` | `150s` |
| `HTTP_MAX_REQUEST_BYTES` | `10485760` |
| `ANALYSES_PER_HOUR` | `30` на экземпляр |
| `ANALYSES_PER_CLIENT_MINUTE` | `3` на сетевой адрес |
| `MAX_CONCURRENT_ANALYSES` | `2` на экземпляр |
| `AI_PROVIDER` | `yandex` |
| `PHOTO_PRESETS_FILE` | пусто; путь к приватному JSON с согласованными результатами |
| `YANDEX_API_KEY` | нет |
| `YANDEX_FOLDER_ID` | нет |
| `YANDEX_MODEL` | `qwen3.6-35b-a3b` |
| `YANDEX_BASE_URL` | `https://ai.api.cloud.yandex.net/v1` |
| `YANDEX_TIMEOUT` | `90s` |

Альтернативный провайдер `AI_PROVIDER=openai` использует `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` и `OPENAI_TIMEOUT`. Секреты держите в окружении хостинга, не в Git.

Лимиты возвращают 429 и `Retry-After`. Каждый HTTP-вызов провайдера, включая повтор после некорректного JSON, расходует отдельную единицу часового и клиентского лимита. В журнал `provider_attempt` попадают номер попытки, длительность, HTTP-статус и токены, если провайдер их вернул; фото, ключи и текст ответа туда не входят. Число токенов не является расчётом стоимости в рублях. Адрес клиента берётся из сетевого соединения; заголовок `X-Forwarded-For` не считается доверенным. Лимиты хранятся в памяти одного экземпляра, поэтому при масштабировании для общего бюджета нужен gateway или общий rate limiter.

Весь AI-анализ ограничен 110 секундами, включая повтор. Повтор некорректного ответа допускается один раз и только если осталось хотя бы 15 секунд. Таймаут отдельного HTTP-вызова по умолчанию 90 секунд.

Для Yandex API ключу нужен scope `yc.ai.foundationModels.execute`, а сервисному аккаунту роль `ai.languageModels.user` для каталога. Подробнее в [документации Yandex AI Studio](https://aistudio.yandex.ru/en/docs/ai-studio/operations/generation/multimodels-request).

Строгий контракт признаков: [openapi/ai-features.schema.json](openapi/ai-features.schema.json). Он не содержит национальности, религии, привлекательности, здоровья и иных чувствительных выводов. HTTP контракт: [openapi/openapi.yaml](openapi/openapi.yaml).

Для Qwen3.6 запрос использует JSON-режим с небольшим бюджетом рассуждения. Сервер проверяет все обязательные поля и диапазоны чисел после ответа модели. Кадр с видимой частью одежды получает предварительную оценку; качество фото не входит напрямую в балл стиля. Если модель видит не одного человека, совсем не видит одежду или возвращает уверенность ниже 20, сервер отдаёт `low_confidence` без категории, уровня и оценки. Этот порог требует дальнейшей проверки на согласованном наборе фотографий.
